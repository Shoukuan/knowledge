# FreeRTOS 内存管理

FreeRTOS 提供五种 `pvPortMalloc()` / `vPortFree()` 实现方案，编译时选择一种。

## 五种方案速查

| 方案 | 释放 | 合并 | 确定性 | 适用场景 |
|------|------|------|--------|----------|
| heap_1 | ❌ | N/A | ✅ O(1) | 只分配不释放，安全关键系统 |
| heap_2 | ✅ | ❌ | ❌ O(n) | 已废弃，用 heap_4 替代 |
| heap_3 | ✅ | 取决于 libc | ❌ | 已有标准 C 库，不需确定性 |
| heap_4 | ✅ | ✅ | ❌ O(n) | **推荐通用方案** |
| heap_5 | ✅ | ✅ | ❌ O(n) | 多个非连续内存区域 |

## heap_1：最简单

- 单一静态数组，指针递增分配，永不释放
- `vPortFree()` 不实现
- 无碎片风险，适合启动时一次性分配

## heap_2：最佳适配（已废弃）

- 空闲块链表 + 最佳适配算法
- **不合并**相邻空闲块 → 易碎片化
- 官方建议使用 heap_4 代替

## heap_3：标准库封装

- 直接调用 `malloc()` / `free()`
- 用调度器挂起/互斥锁保证线程安全
- 执行时间取决于 C 库实现，非确定性

## heap_4：最佳适配 + 合并（推荐）

- 与 heap_2 相同算法，但 `vPortFree` 时合并相邻空闲块
- 空闲链表按地址排序
- 抗碎片能力显著优于 heap_2

## heap_5：多内存区域

- 算法同 heap_4，但内存池可跨多个不连续物理区域
- 使用前必须调用 `vPortDefineHeapRegions()`
- 适用场景：片内 SRAM + 片外 SRAM 组合

## 关键配置

```c
// FreeRTOSConfig.h
#define configTOTAL_HEAP_SIZE     ( ( size_t ) 32768 )  // heap_1/2/4
#define configAPPLICATION_ALLOCATED_HEAP  1              // 用户提供 ucHeap[]
```

## 决策流程

```
需要释放？ → 否 → heap_1
        → 是 → 多物理区域？ → 是 → heap_5
                            → 否 → 需确定性？ → 是 → heap_3 (或用静态分配替代)
                                            → 否 → heap_4
```
