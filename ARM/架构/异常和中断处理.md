# 异常和中断处理

ARM 架构将异常定义为需要内核处理的事件，按触发源分为同步和异步两类。

## 核心概念

- **同步异常**：由指令执行直接导致，如 data abort、undefined instruction、SVC
- **异步异常（中断）**：IRQ、FIQ、SError，由外部事件或信号触发
- **异常级别**：EL0（用户态）→ EL1（内核）→ EL2（Hypervisor）→ EL3（Secure Monitor）
- **向量表**：每个 EL 独立，16 个 entry × 64 字节，基址在 `VBAR_ELx`

## 异常处理流程

1. 硬件自动保存 PSTATE → SPSR，返回地址 → ELR
2. 切换到目标异常级别和对应 SP
3. 跳转到向量表对应 offset
4. 软件保存上下文（通用寄存器），解析 ESR 判断异常原因
5. 分发到具体处理函数
6. 通过 `eret` 返回：SPSR → PSTATE，ELR → PC

## 关键寄存器速查

| 寄存器 | 用途 |
|--------|------|
| `VBAR_EL1` | 异常向量表基地址 |
| `ESR_EL1` | 异常综合症（EC/IL/ISS 字段） |
| `ELR_EL1` | 异常返回地址 |
| `FAR_EL1` | 故障地址（同步异常） |
| `SPSR_EL1` | 异常前的处理器状态 |
| `DAIF` | 中断掩码（bit0=FIQ, bit1=IRQ） |

## 典型场景

### 系统调用（SVC）
用户态 → `svc #0` → 同步异常 → 向量表 entry `lower EL, AArch64` → ESR 解析出 Svc → 系统调用表分发

### 缺页中断（Data Abort）
访问未映射地址 → MMU 产生 abort → data abort 异常 → ESR.EC + FAR 定位原因 → `do_page_fault()` → 分配物理页或发 SIGSEGV

### 外设中断（IRQ）
GIC 仲裁 → IRQ 信号 → `handle_arch_irq` → GIC driver 读 IAR → 调用 irq_handler → 写 EOI 结束

## 开发要点

- 向量表每项仅 0x80 字节，通常放跳转指令
- `DAIFClr` / `DAIFSet` 控制局部中断开关
- 同步异常的 ELR 指向故障指令本身，异步异常指向下一条
- SVC 调用后 ELR 自动 +4，返回时无需修正
